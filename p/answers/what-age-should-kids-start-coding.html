What age should kids start coding?

There is no single right age, but there is a useful rule of thumb: if a child can read simple sentences and follow a two-step instruction, they can start coding.

Ages 5-7: coding without typing

At this age the goal is not syntax, it is sequencing - understanding that a computer does exactly what you tell it, in order, and nothing else. Drag-and-drop blocks work well because a child can build a working program without fighting a keyboard. Expect sessions of 10-15 minutes. Frustration usually means the session ran long, not that the child 'isn't ready'.

Ages 8-10: the switch to typed code

Somewhere around 8, most kids can handle typing real code. This is the age where print("Hello") stops being intimidating and starts being satisfying. Typos become the main obstacle, which is actually the lesson: computers are literal. Keep sessions to 20-30 minutes and let them build something silly of their own after each lesson.

Ages 11-13: real projects

Now a child can hold a whole project in their head - variables, loops, functions, and a goal they chose themselves. This is when coding becomes self-motivating, because they can finally build the thing they actually wanted. The job of a parent shifts from teaching to unblocking.

Ages 14+: depth

Older beginners move faster than younger ones and can skip most of the scaffolding. If a teenager is starting from zero, do not put them in a program designed for eight-year-olds; they will quit. Start at typed code immediately.

The signs a child is ready

They ask how something on a screen works. They notice when a game is unfair. They like puzzles with a right answer. They enjoy building - blocks, Lego, Minecraft. None of these is required, but each one predicts an easier start.
